# Academic originality and DrillBit preparation

This guide is for producing work that is genuinely your own. It is not a method for bypassing or manipulating similarity detection.

## What must be your own work
- Your problem framing, objectives, assumptions and success criteria.
- Your interpretation of the dataset and its limitations.
- Your decisions about cleaning, feature handling and evaluation.
- Your discussion of EDA findings and statistical test results.
- Your explanation of model comparisons and final model selection.
- Your conclusion and proposed improvements.
- Your own GitHub development history and viva explanations.

## What must be attributed
- The UCI Bank Marketing dataset and its original research citation.
- External articles, papers, diagrams, code examples or explanations that materially informed your work.
- Third-party libraries and tools where appropriate.

## Source-code integrity
The supplied Python implementation is a starting implementation. Read it, run it, test it and make project-specific decisions you can explain. Do not claim code as independently authored if you copied it from another source. Keep attribution for any external code that you adapt. Do not add meaningless edits merely to make code look different.

## Report integrity
1. Run the project and use only your actual output values.
2. Write interpretations after inspecting your own plots and metrics.
3. Cite sources close to the claims they support.
4. Use quotation marks for any exact wording reproduced from a source, with a citation.
5. Do not fabricate references, results, GitHub stars, pull requests, LinkedIn engagement or screenshots.
6. Keep a copy of your drafts, experiment outputs and genuine commit history.

## Similarity reports
Similarity tools can flag standard terminology, dataset names, references, assignment headings and common code structures. A similarity percentage is not itself a plagiarism verdict. Review matched passages in context and follow your institution's rules. Only your institution can confirm its DrillBit settings, exclusions and acceptable threshold.

## Before submitting
- Verify every number against `outputs/`.
- Verify every reference exists and supports the cited statement.
- Make sure you can explain every important code block.
- Check that the report, notebook/scripts and README describe the same methodology.
- Ask your faculty if there are institution-specific requirements you cannot access.
